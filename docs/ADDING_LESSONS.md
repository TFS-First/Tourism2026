# إضافة درس مع الحفاظ على التصميم

## المبدأ

كل درس ملف بيانات مستقل. القاموس والقواعد والتدريبات والكتابة والقائمة تقرأ بياناته وتستخدم العرض المشترك.
لا تُنشئ صفحة أو نافبار أو قالب رموز جديدًا للدرس. لا تغيّر ترتيب الكلمات القديمة؛ مراجع التنقل الحالية تستخدم ترتيبها.

## الخطوات

1. احصل على صفحات الدرس والطبعة المعتمدة. لا تعتبر مثالًا من الذاكرة نقلًا مطابقًا للكتاب.
2. أنشئ `src/lessons/lesson-04.json` باستخدام `lesson-template.json` المجاور كنقطة بداية.
3. اختر معرفًا فريدًا مثل `lesson4`، وأكمل الأسماء والعدد والمحتوى. النموذج فارغ للتنظيم، وليس درسًا علميًا جاهزًا.
4. أضف اسم الملف مرة واحدة في نهاية `src/lessons/registry.json`. ترتيب القائمة هو ترتيب الدروس في التطبيق.
5. نفّذ البناء والفحوص والمراجعة البصرية. لا تنشر درسًا فارغًا أو أمثلة تجريبية.

## حقول الدرس

- `id`, `number`, `titleAr`, `titleEn`: هوية مستقرة وترتيب وعناوين الدرس. استخدم نفس `titleEn` في أسئلة الكتابة لربط مرشحها.
- `grammar`: نفس بنية القواعد الحالية: `id`, `titleAr`, `titleEn`, `badges`, `rules`.
  - كل قاعدة لها `id` فريد مثل `rule-4-1`، و`ruleNum`، والعناوين والشروح.
  - `badges[].id` يجب أن يطابق قاعدة موجودة.
  - الأنواع المدعومة حاليًا في العرض: `grid` وفرع العرض العام للبيانات المنظمة. افحص `GrammarSection.jsx` قبل اختراع نوع جديد.
  - انسخ *بنية* قاعدة مشابهة فقط، ثم أدخل شرح الدرس من مصدره. لا تنسخ محتوى درس قديم باعتباره درسًا جديدًا.
- `vocabulary`: `lesson`, `lessonEn`, `words`؛ كل كلمة تحتوي `h`, `trans`, `meanEn`, `meanAr`.
- `exercises`: مصفوفة تمارين الدرس. القراءة تستخدم `h`, `trans`, `meanEn/meanAr`. الرسم يستخدم `correctH` بدل `h`.
- `exercisePresentation`: `kind` إما `drawing` أو `reading`، مع `titleEn`, `titleAr`, `description`, `icon` لعنوان وتعليمات التمرين؛ الشكل مشترك.
- `typingQuestions`: نفس الحقول الحالية، مع `id` فريد و`lesson/lessonEn` مطابقين للدرس و`h/trans/hint` والمعاني.
- `typingIcon`: أيقونة مرشح درس الكتابة، دون تغيير المكوّن المشترك.
- `quizQuestions`: أسئلة اختيار من متعدد. المعرفات فريدة على مستوى كل الدروس والبنك المشترك. استخدم الفئات الحالية `alphabet`, `vocabulary`, `grammar`، ونفس حقول بنك الاختبارات العام.
- يمكن إرفاق `source` لتوثيق الكتاب والطبعة والصفحات والمراجع دون عرضه للزائر.

القوائم الخالية تُقبل أثناء التأليف، لكن لا تنشر درسًا ناقصًا باعتباره مكتملًا.
تظهر الدروس تلقائيًا في قائمة المحتوى والقاموس والقواعد والتدريبات عند تسجيلها. أسئلة الكتابة تظهر في مرشحاتها تلقائيًا.
إذا زاد عدد مرشحات الكتابة عن سبعة، يستخدم التطبيق قائمة اختيار بدل ازدحام أزرار الدروس.
أسئلة الاختبار الجديدة تُضم للبنك العام؛ الاختبار الحالي يختار عشر أسئلة كما كان.

## الهيروغليفية

استخدم `*` للتجاور، `:` للتكديس و`()` للتجميع وفق المصدر؛ لا تغيّر الرموز أو ترتيبها لتقليل الحجم.
`VocabularyGlyph` يضبط حجم الكلمة حسب الكارت؛ `HieroglyphBlock` يفسّر ترتيب الرموز؛ أمثلة القواعد تستخدم `IllustrativeExamplesBlock`.
قارن كل كتابة بالمصدر وراجع الأجزاء المركّبة بصريًا على الموبايل والكمبيوتر.

## التحقق والنشر

```sh
npm run build
npm run check
npm test
```

راجع الدرس في الأقسام الأربعة. اختبر البحث بالعربي وبالنقحرة، فتح عناوين درس مطوي، كشف الحل والرسم والكتابة والاختبار.
اختبر 320 و390 و768 و1280 بكسل، والنافبار أثناء النزول والعودة للأعلى.
ارفع `src/` وأي ملفات بناء تغيّرت (`index.html`, `assets/app.js`, `assets/app.css`) معًا.
لا تعالج فشل اختبار حماية المحتوى بتحديث البصمات تلقائيًا. إذا كان التغيير تصحيحًا علميًا معتمدًا، وثّق السبب والمصدر وحدّث المرجع بعد المراجعة.

## الشرح التمهيدي داخل القاعدة

عند الحاجة إلى أمثلة مبسطة، ضع `learningGuide` اختياريًا داخل القاعدة نفسها في `grammar.rules`، لا في أعلى الدرس. يعرضه `GrammarLearningGuide` بعد عنوان القاعدة. لكل خطوة `title` و`tabLabel` و`explanation` و`pairs` و`note`؛ ولكل مثال `h` و`trans` و`arabic` و`literal` و`analysis`. أضف `source` وميّز الجمل التعليمية المؤلفة من اقتباسات المصدر. الرموز تستخدم `VocabularyGlyph` و`HieroglyphBlock` المشتركين؛ لا تنسخ رسامًا جديدًا أو تكدس العلامات لمجرد ملاءمة العرض.
